# Общее
- В README.md должна быть инструкция как запустить проект на windows и linux. Поддерживай файл в актуальном состоянии.
- Не переименовывай уже написанные классы, функции, переменные. 
- Не меняй бизнес логику.
- Явные действия в коде лучше неявных, короче - лучше длинного, простое - лучше сложного.
- Если решение текущей задачи затрагивает работу стороннего кода, можно вносить минимальнные измененния для сохранения работоспособности.

# Комментарии
- Пиши комментарии на русском языке и только для:
	- *Больших или сложных* функций, где *требуется* дополнительный контекст происходящего;
	- классов, с целью обоснования их предназначения;

## Pyrefly
### Config
```toml
   [tool.pyrefly]
   preset = "default"
   project-excludes = ['**/.venv', '**/tests', '**/migrations']

   [tool.pyrefly.errors]
   bad-override = false
   bad-assignment = false
```
* Не используй `isinstance()` для `type narrowing`. Я предпочитаю `var: type = value`.

Перед завершением задачи, которая изменяла Python-файлы надо выполнить:

3. Если есть какие-то ошибки - исправь их.

- К API обязательно должна вестись документация с помощью `OpenAPI`. Всегда поддерживай ее в актуальном состоянии.

- Перед выполнением задачи, затрагивающей Django-код, сначала предоставь краткий план изменений. Для каждого пункта указывай только то, что относится к текущей задаче. Если пункт не применим — явно укажи это. Обязательно запрашивай согласие на применение плана и изменении кода. Не меняй файлы пока я не подтвержу.

## Code style
- При работе со словарями используй `.get(key)` метод в случаях, когда отсутствие значения является предусмотренным сценарием работы. В противном случае используй синтаксис `dict[key]`.
- Добавляй обработку `None` только в случаях, когда отсутствие значения является предусмотренным сценарием работы.
